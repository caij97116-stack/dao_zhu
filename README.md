# 岛主历险记 (dao_zhu)

一个 SillyTavern 前端扩展，让「正则 + 脚本(iframe/JS) + CSS」的聊天美化渲染在
**SillyTavern 1.17 / 1.18 / 1.19 及未来小版本**上稳定、不卡顿、不爆代码；
并附带一个**岛民名册悬浮窗**，帮你管理「切身份 / 找角色卡 / 配世界书 / 美化自适应」等日常痛点。

**性能目标**：即使聊天楼层极高（**数百层、上千层甚至更多**），滚动/渲染依然不卡顿，
每一层的自动美化都能正确触发、渲染完成、正确显示——不丢楼、不重绘、不越跑越慢。

---

## 解决的四个问题 + 三大新增场景

| # | 痛点 | 本扩展的做法 |
|---|---|---|
| 一 | 正则/脚本冲突 + 卡顿 | 增量更新 + 防抖，用 `MutationObserver` 只盯新增消息节点，不轮询、不全量重绘；监听器及时清理防内存泄漏。目标是在数百层、上千层的超高楼层聊天里仍保持流畅、每一层都渲染完成、不越跑越慢。 |
| 二 | 正文爆代码 | 模糊正则对轻微格式波动更宽容 + 多套兜底；即使主正则没命中，也隐藏/降级原始标签，绝不裸奔；渲染中途报错只显示成品、不显示半成品。 |
| 三 | 跨版本兼容 | 全部用「特性检测」（判断函数/属性是否存在）而非写死版本号；`manifest.json` 版本下限放宽、不设上限；旧 API 缺失走 fallback。 |
| 四 | AI 不读正则 | **内置抗弱模型格式指令**（默认自动注入聊天系统提示，**无需你手动复制到预设/角色卡**）+ 模糊正则多兜底 + 「格式校验 + 自动修复」中间层。 |
| 五 | 切身份麻烦 / 卡多找不到 | **岛民名册悬浮窗 · 名册页**：搜索 + 排序 + 收藏 + 标签筛选，点一下即切身份；并按「世界书 / 标签」双维度分组，把关联卡显式聚到一起。 |
| 六 | 美化只适配 PC 或只适配手机 | **岛民名册悬浮窗 · 美化页**：①「整体美化自适应」注入响应式基线层，只修布局不碰配色，PC-only / mobile-only 主题都能正常显示；②「卡片美化自适应」让本插件的 `[card]` 卡片 PC/手机都好看，并提供「检查并重渲染全部卡片」。 |
| 七 | 世界书 / 脚本被拆散找不到对应卡 | **岛民名册悬浮窗 · 绑定页**：手动把「角色 ↔ 世界书」**勾结绑定/解绑**，写入角色卡权威字段 `data.extensions.world`，名册区的「按世界书」分组实时同步。 |

## 安装

### 方式 A：从 GitHub 一键安装（推荐）
1. 打开酒馆 → 顶部拼图图标「Extensions」→ **Install Extension**；
2. 粘贴仓库地址：`https://github.com/caij97116-stack/dao_zhu`；
3. 点击 Install，完成后**重载酒馆（Reload）**。

### 方式 B：手动放置
把本仓库克隆/解压到 `public/scripts/extensions/third-party/dao_zhu/`，然后重载酒馆。

> 兼容性：`manifest.json` 的 `minimum_client_version` 为 `1.17.0`，**只设下限、不设上限**，
> 因此 1.17 / 1.18 / 1.19 及更高小版本均可安装。所有 API 调用均做特性检测，缺失即安全降级，绝不拖崩酒馆。

## 怎么打开「岛民名册」悬浮窗

> 很多人第一次找不到入口，这里单独说明：

- 安装并重载后，在**聊天输入框的原生按钮栏**（左下角，与 ☰ 汉堡菜单 / 🪄 魔法棒 **同一排**）里的「📒 名册」按钮点一下，即可打开/关闭悬浮窗。
- 找不到这个按钮？去 **Extensions → 岛主历险记** 设置面板，点 **「打开岛民名册悬浮窗」** 按钮也能开；
  若该按钮被你关掉了，同样在设置面板勾选 **「在聊天输入框原生按钮栏显示『📒 名册』按钮」** 即可恢复。
- 面板本身就是**可折叠抽屉**（与酒馆助手 / 鸡尾酒 等原生扩展一致）：点 **📖 岛主历险记** 标题栏展开/折叠。
- 悬浮窗可**拖动标题栏**移动，位置会被记住（刷新/重开酒馆回到原位）；顶部三个标签页：**名册 / 美化 / 绑定**。

## 配置（设置面板）

安装并重载后，进入 **Extensions → 岛主历险记** 即可看到设置面板。

> 面板是**可折叠抽屉**（对齐酒馆助手 / 鸡尾酒 等原生扩展的观感）：默认折叠，点 **📖 岛主历险记** 标题栏即可展开/收起，不会把扩展页面撑得很长。

展开后可见：

- **🎨 界面皮肤**（M17）：三选一下拉框，**切换即刻生效**（纯 CSS，不重渲染消息）。详见下方「界面皮肤」专节。
- **启用自动美化**：总开关。关闭后，已渲染消息还原为原始文本。
- **允许卡片内 html 富文本字段**：开启后，卡片的 `html=` 字段经酒馆内置 DOMPurify 消毒后渲染；若环境无 DOMPurify，则自动转义兜底，**不会注入脚本**。
- **允许卡片内 iframe 字段**：开启后，`iframe=` 字段仅允许 `http/https`（`javascript:`/`data:` 一律拒绝），并以 `sandbox="allow-scripts"` 隔离。
- **用当前设置重新美化当前聊天**：改动上述开关后，点击它即时应用到当前聊天（靠 `dataset.dzOrig` 存原始文本，重渲染不会重复解析渲染产物）。
- **岛民名册悬浮窗（M9+）**：
  - 「在聊天输入框原生按钮栏显示『📒 名册』按钮」—— 控制左下角那个入口按钮的显示（与 ☰ / 🪄 原生按钮并列）；
  - 「打开岛民名册悬浮窗」—— 即使按钮隐藏也能临时打开面板。
- **抗弱模型 · 格式指令（已内置，自动注入）**：本扩展默认把这段「要求模型完整、规范输出 `[card]…[/card]`」的指令**自动注入到聊天系统提示**，**无需你手动复制**，也不改动你的预设/角色卡文件。
  - **「自动内置注入格式指令」开关**：默认**开启**（即内置生效）；关掉则退回手动模式，用下方的 **复制格式指令（手动备用）** 按钮自行粘进预设/角色卡做微调。
  - 若你的酒馆版本拿不到提示注入事件，扩展会**静默降级**（不报错、不影响发送），此时改用「复制」按钮手动粘进预设即可。
- **📱 小手机工坊**（入口就在这里，不用去别处找）：
  - 「显示小手机模板条」—— 控制聊天输入框上方那条横向模板条的显示；
  - 「📱 打开小手机工坊」—— **直接打开全屏工坊**（新建 / 编辑 / AI 帮写 / 导入导出包），等同点模板条上的「⚙ 管理」；
  - 「启用自有 OpenAI 兼容 API」+ **Base URL / API Key / 模型** —— AI 帮写的后端配置。**勾选并填好即用自有 API**；不勾选或留空则走**酒馆同连接**（复用酒馆本地服务端，无需自带 key）。

### 岛民名册 · 三个标签页怎么用

| 标签页 | 能做什么 | 关键操作 |
|---|---|---|
| **名册** | 找角色、切身份 | 搜索框（名字/标签/世界）、排序（名字/收藏/最近/聊天最多）、收藏星标、标签筛选；视图可切「列表 / 按世界书 / 按标签」；点角色行即 `openCharacterChat` 一键切身份。 |
| **美化** | 解决美化只适配一端 | ①「整体美化自适应」：开 →（可点「检测并应用」）→ 注入响应式基线层，修复 PC-only / mobile-only 主题崩坏；可手动选「按桌面/按手机」、可填「自定义补丁 CSS」。<br>②「卡片美化自适应」：点「检查并重渲染全部卡片」让 `[card]` 卡片 PC/手机重排；`style.css` 已加移动端断点。 |
| **绑定** | 把拆散的世界书/角色卡勾结 | 选角色 + 填世界书名（带已有世界书候选补全）→ 绑定；下方列出当前绑定状态，可按世界书筛选、可一键解绑。写入角色卡权威字段 `data.extensions.world`，名册「按世界书」分组实时同步。 |

> 技术边界说明（务必知晓）：「整体美化自适应」注入的是一套**稳健的响应式基线**（尊重主题自带的 `--SmartTheme*` 颜色与变量，只修布局崩坏：固定宽度改流体、补断点、面板可滚动），无法 100% 复原每一个特殊主题原作者意图；极少数结构特殊的主题，可用「自定义补丁 CSS」框手动补漏。这是目前最稳、最通用的做法。

### 小手机工坊（M16：适配酒馆内小手机的底部模板）

> 在聊天输入框**上方**会多一条独立的小手机模板条（与 Quick Replies / 输入助手底条互不干扰）。点任意模板即运行该脚本（运行器见 M16-D）；点右侧 **「⚙ 管理」** 打开全屏「小手机工坊」编辑器。

| 能力 | 怎么用 |
|---|---|
| **底部模板条** | 聊天框上方横向滚动的胶囊按钮，点一下即运行对应脚本；模板太多会提示「去管理」；右侧 ▾ 可收起为 📱 把手（移动端安全区适配，不挡输入）。 |
| **全屏编辑器** | 「⚙ 管理」打开：左侧模板列表（编辑/复制/删除），右侧表单。 |
| **模板名 / 运行方式** | 模板名自定义；运行方式可选 **运行 STscript**（以 `/` 开头的斜杠命令，由 M16-D 执行）或 **仅插入文本**（直接塞进输入框，供你发送/改写）。 |
| **保存到作用域** | 三选一：**同层(当前聊天)** / **跨层(全局)** / **跨层(角色专属)**；保存时自动从其它作用域移除同 id，避免重复。 |
| **✨ AI 帮写** | 在「📝 告诉 AI 你想要什么」框里描述效果 → 生成脚本填入**预览框**（不直接覆盖）。后端优先级：**自有 OpenAI 兼容 API**（设置里填 baseUrl/apiKey/model）> **酒馆同连接**（复用酒馆本地服务端，无需自带 key）。 |
| **🔒 内置底层提示词** | 工坊每次 AI 帮写都会**自动注入一条隐藏的系统提示词**（常量 `PHONE_SYSTEM_PROMPT`，不在 UI 暴露、不进设置、无需你手动塞世界书/预设）：强制 AI 只当代码生成器、**忽略角色人设/世界观/世界书/角色扮演语境**、只输出干净产物。这是内置的，你看不到也无需维护。 |
| **插入到模板** | 审查 AI 预览后点「插入到模板」才落进代码区；按当前「插入方式」**替换**或**联合正文(追加)**，省得手敲。 |
| **↩ 撤回** | 编辑器维护撤回栈，AI 插入 / 保存 / 删除都能一键撤回（删除的撤回会把模板重新加回）。 |
| **插入方式（联合正文）** | 文本模板的运行行为：选 **替换**(覆盖聊天输入框)** 或 **联合正文**(追加到输入框现有正文)**，运行时（M16-D）即按此把模板塞进聊天输入框、和正文合并成一条消息。逻辑由纯函数 `combineWithBody` 实现（node 已测）。 |
| **▶ 试跑** | 调 M16-D 运行器跑当前模板：STscript 走 `executeSlashCommands`，纯文本按「插入方式」塞进聊天输入框（替换/联合正文）。需先保存模板。 |
| **底部条点按钮运行** | 点底部条上的模板胶囊即运行（STscript 执行 / 纯文本进输入框）；底层统一走 M16-D 运行器，特性检测、缺 API 自动降级提示。 |
| **📦 导出 / 📥 导入包** | 把全部模板导出为**命名 JSON 包**（自定义脚本名 `xxx.json`）；导入包按 id 合并进全局（新增/更新分别计数，跳过非法条目）。 |

> 技术边界说明（务必知晓）：「AI 帮写」会**自动注入内置隐藏系统提示词** `PHONE_SYSTEM_PROMPT`，让任何被调用的 AI 只写代码、不受你的角色/世界观干扰。**自有 OpenAI 兼容 API** 走它完全隔离（请求只含我们的 `system`+`user` messages）；**酒馆同连接**走酒馆本地端点 `/api/openai/chat/completions`（由服务端注入你的 key），个别酒馆版本该端点可能仍把角色上下文并入请求，此时模型被指令忽略、但若你要彻底隔离请用自有 API。不同酒馆版本端点路径可能不同，未命中时按钮会明确提示改用自有 API。AI 网络调用与模板运行均属运行时行为，请在真实实例按 F12 确认。跨作用域持久化、包导出/导入、`buildOpenAiMessages`（含隐藏 system 规则）、`combineWithBody` 等纯逻辑已由 `tests/phone-scripts-editor.test.mjs` 在 node 实测。

## 界面皮肤（M17 · 情绪拼贴）

### 三套皮肤（设置面板顶部下拉框，切换即刻生效）

| 皮肤 | 观感 | 适合 |
|---|---|---|
| **拼贴 · 墨（Cinder）**〔默认〕 | 忠实美化稿：暗色纸面 + 笔记本打孔 + 胶带 + 回形针 + 噪点，衬线展示标题 | 想要"出片"质感；暗色/中性主题 |
| **拼贴 · 纸（Paper）** | 同样的拼贴质感，但底色与文字**跟随你当前的酒馆主题变量**（`--SmartTheme*`） | 亮色主题、或不想让卡片突然变黑 |
| **经典（Classic）** | M16 之前的简洁描边卡片，不加任何质感 | 只想最低干扰 / 排查问题时 |

- 皮肤只作用于**本扩展自己的 `.dz-` 元素**（消息卡片、岛民名册悬浮窗、名册行、小手机模板条），**不碰酒馆任何原生 DOM、也不改酒馆主题变量**；
- 切换皮肤**只换 `<html>` 上的类 → 纯 CSS 生效**，不需要重渲染消息，上千楼也不卡；
- 皮肤值写坏（乱填/空/null）会**自动回落到默认皮肤**，不会让界面变空白。

> 皮肤的实际效果可以离线预览：用浏览器打开 `skin-preview.html`（它直接引用扩展真实的 `style.css` 与 `src/renderer.js`，所以看到的就是实机效果），顶部可切换三套皮肤并模拟酒馆的暗色/亮色主题。

### 这份「美化稿」原本的问题（已逐条修掉）

外部给来的是一份**独立整页 HTML 演示稿**（Cinder 色系 + 打孔/胶带/回形针/灰度照片/衬线标题/噪点）。它作为"整页"是好看的，但**直接塞进酒馆会出事**，所以这里只翻译它的质感、不改它的作用域：

| # | 原稿写法 | 直接用的后果 | 改造后 |
|---|---|---|---|
| 1 | `body::before/after` 全屏 `position:fixed` 覆盖层 | 会**盖住整个酒馆聊天区**（背景图 + 噪点糊在全局，还带 `z-index:-2/-1`） | 删掉全局覆盖层；噪点只加在 `.dz-card`/`.dz-nav` 内部的伪元素上 |
| 2 | `* { margin:0; padding:0 }` | **重置掉酒馆与所有第三方扩展**的排版 | 完全移除，皮肤只作用于 `.dz-` 元素 |
| 3 | 写死 `background:#000` + 固定灰白文字色 | **无视 SillyTavern 主题**，亮色主题下卡片变成黑块、字看不清 | 配色改走 CSS 变量：`cinder` 保留原稿暗色调；`paper` 读取 `--SmartTheme*` 跟随主题 |
| 4 | 外链 Unsplash 图片 + Google 字体（Cormorant Garamond） | **离线不可用**、有隐私与加载失败问题，字体拉不到就掉字形 | 零外链：噪点用内联 SVG（data-uri），字体只用系统衬线栈（Songti SC / Noto Serif SC / Georgia） |
| 5 | 展示型组件（`hero` / `palette-strip` / `photo-stack`）与卡片结构对不上 | 无法直接套到 `[card]` 渲染结果上 | 翻译成卡片能承载的质感：打孔列、胶带、回形针、字段行 hover 位移、灰度图片滤镜、衬线标题、引言式 `__notes` |
| 6 | 打孔用 `mask-image` 写死 6 个固定坐标 + `mask-composite` | 卡片一高就**对不上孔**，且遮罩会**把卡片阴影裁掉**，兼容性也差 | 改成 `radial-gradient` + `background-repeat: repeat-y` 的圆点列，任意高度都均匀，不动阴影 |
| 7 | 样例文案/图片（内永绘里、松子的一生、两张 Unsplash）硬编码在结构里 | 等于把演示内容塞进用户聊天 | 全部删除，皮肤只留样式，内容仍由 AI 输出的 `[card]` 决定 |

> 补充：皮肤也做了 `prefers-reduced-motion` 适配（系统开启"减少动效"时自动关掉位移/滤镜过渡）与 480px 窄屏断点。

### 顺带修掉的两个卡片渲染 bug（M17 验收时挖出，与皮肤无关但影响所有人）

用真实渲染截图做皮肤验收时，发现卡片内容会"凭空消失"，排查出**两个历史缺陷**，已修复并补了回归测试：

| 缺陷 | 症状 | 根因 | 修复 |
|---|---|---|---|
| **显式 `__notes=…` 被静默吞掉** | AI 若把独白写成 `__notes=我不习惯被爱。` 这一行，**整段独白在界面上完全不显示**（裸文本行反而正常） | 解析层对 `__notes` 有两条来源：裸文本行存**数组**、显式字段行存**字符串**；`renderCardHtml` 只判 `Array.isArray`，字符串直接被跳过 | `renderer.js` 兼容数组与字符串两种形态（`__notes` 缺失才不渲染），保留换行 |
| **显式 `__notes=` + 裸文本行混用会抛异常** | 同一张卡两种写法都有时，解析直接 `TypeError: fields.__notes.push is not a function`（被外层 try/catch 兜住 → **该楼美化整体失败**，只显示降级原文） | `parseCardBody` 里 `fields.__notes.push(t)` 没判断已有值是字符串还是数组 | `transform.js` 先判断类型：是数组就续上、是字符串就先归一成数组再接 |
| **空值字段行被当正文显示**（附带修复） | 弱模型留一个空字段（`__notes=` / `备注:` 后面忘填），界面上会**直接显示字面量 `__notes=`** | 字段正则要求值非空，空值行落进"裸文本行"分支，被塞进备注 | 新增 `EMPTY_FIELD_RE`，空值字段行识别后**丢弃**，不当内容也不当字段 |

> 回归测试：`tests/renderer.test.mjs` +8 项、`tests/transform.test.mjs` +11 项，覆盖显式/裸文本/混用/空值/转义/换行。**全量 458 通过 / 0 失败。**

## 抗弱模型格式指令（内置自动注入，无需复制）

弱模型常出现两类问题：① 格式漂移（大小写/空格/漏闭合）；② 输出到一半就断掉、漏字段、留半个标签。
这段指令刻意做到「重复性强、歧义小」，并显式要求**必须完整输出闭合并一次给全**。

**它默认由扩展自动注入聊天系统提示（内置生效，你不需要复制任何东西）**；完整文本见 `src/instruction.js` 的 `FORMAT_INSTRUCTION`，要点摘录：

```
【结构化信息格式指令（必须严格遵守）】
…只在正文中使用下面这一种格式…
[card]
title=面板标题
theme=blue
字段名: 字段值
[/card]
硬性规则：
1. 必须以 [card] 开头、以 [/card] 结尾，必须成对完整闭合，绝不漏写 [/card]。
2. 标签名固定为 card（小写英文）。
3. 字段用「键: 值」或「键=值」，分隔符前后不加空格。
4. 可输出多个块，但每个都独立完整闭合。
5. 普通对话写在 [card] 块之外。
6. 内容再长也必须一次性完整输出，绝不在中间断句、绝不省略字段、绝不留半个标签。
```

## 兼容性（与其他扩展共存）

本扩展以「**最小侵入、命名空间隔离、特性检测降级**」为底线设计，可与酒馆助手 / 鸡尾酒 / 柏宝箱等常见扩展共存。对应任务的 M15 加固已落地（悬浮窗层级、按钮注入去重、卡片防丢恢复、整体美化自适应隔离）。

### 共存原则

- **命名空间隔离**：所有 DOM 节点、CSS 类、data 属性均以 `dz-` / `dzOrig` / `data-dz-*` 前缀，不污染全局，也不与第三方类名冲突（已刻意不约束酒馆通用浮窗类 `.floating-panel`）。
- **只改自己的内容**：消息处理器仅在消息含 `[card]` 时才改写 HTML；不含 `[card]` 的楼一律交还给其他美化插件（如酒馆助手的状态栏）处理，互不插手。
- **卡片防丢恢复**：若某楼的 `[card]` 卡片被第三方插件重写 `innerHTML` 冲掉，扩展会自动检测并恢复（仅对含 `[card]` 的楼生效）。
- **不挡全屏 / 不盖模态**：悬浮窗 `z-index: 9000`（低于酒馆原生模态与图片大图），面板固定尺寸（360×70vh）内部滚动，不遮住聊天区与其他浮窗。
- **按钮不破坏容器**：「📒 名册」按钮用 `appendChild` 注入到**原生按钮栏**（优先左下 `#leftSendForm`，与 ☰ / 🪄 并列；拿不到才降级 `#rightSendForm`），且不改写容器现有按钮/样式，与同区注入的插件（如输入助手）和平共处；注入带显式去重。
- **整体美化自适应（手动可选）**：基线层仅在用户开启时挂载，且仅修布局（流体宽 / 断点 / 面板可滚动 / 图片限宽），不改动主题配色；关闭则对全局零影响。
- **皮肤不越界（M17）**：皮肤只往 `<html>` 增删 `dz-skin-*` 类，CSS 选择器**全部**以 `html.dz-skin-*` 起头、以 `.dz-` 元素结尾（68 条规则已逐条校验），**没有任何 `body{}` / `*` 全局重置、也没有外链资源**；切到「经典」等于皮肤层完全不挂载，对全局零影响。

### 与常见插件的相容性

| 扩展 | 是否兼容 | 说明 |
|------|----------|------|
| 酒馆助手（Tavern Helper / JS-Slash-Runner） | ✅ 兼容 | 它在消息楼层渲染状态栏 / 交互 UI；我们仅在含 `[card]` 的楼接管，其余楼交还它处理。同楼若同时含 `[card]` 与它的状态栏语法，`[card]` 卡片优先（设置里关掉「启用自动美化」即可让出该楼）。 |
| 鸡尾酒（Cocktail） | ✅ 兼容 | 它做启动 / 聊天渲染 / 正则刷新优化（改 `index.html` 级），不改消息 DOM；我们不动 `index.html`，各管各的。 |
| 柏宝箱（ST-BaiBai-Tools） | ✅ 兼容 | 它做长聊 DOM 虚拟化（`content-visibility`）、滚动 / 加载优化；我们用 MutationObserver + 防抖 + 去重与之共存，被它冲掉的卡片会自动恢复。 |
| 输入助手 / Quick Replies / ST-Chat-Jumper 等 | ✅ 兼容 | 互不改写对方注入的节点；悬浮窗层级与它们错开。 |

### 已知边界

- 同一条消息**同时**含 `[card]` 与某个第三方美化识别的语法时，两个插件争同一 `innerHTML`，我们以 `[card]` 卡片优先；如不想争，关闭本扩展的「启用自动美化」即可让出该楼。
- 「整体美化自适应」是手动可选开关；若与某个**全局美化主题**布局冲突，关掉即可（它本是修复 PC-only / mobile-only 主题崩坏的逃生口，极少数结构特殊的主题用「自定义补丁」框手动补漏）。
- 兼容性加固经代码审阅 + node 单测保证；最终叠加效果建议在你的真实酒馆实例上按 F12 控制台确认无报错。

## 版本与备份策略

- 本仓库采用 **里程碑 commit + 关键版本 tag** 的双保险：
  - 每个模块（M1–M16）完成即本地提交，保证中间状态可回溯；
  - 关键可交付基线打 **tag**（如 `v1.0.0`），作为「确认版本」的备份锚点。
- 当前已打 tag：
  - `v0.1.0-format-guard`：改名前的 M1–M7 完成基线（含完整管线 + 设置面板 + 单测），作为历史备份锚点；
  - `v0.2.0`：岛主历险记 发布版（改名后的可交付版本）；
  - `v0.3.0`：岛主历险记 + 岛民名册悬浮窗（M8–M14 全量）。
  - `v1.0.0`：小手机工坊全量（M16-A~D：底部模板条 / 全屏编辑器 / AI 帮写 / 运行器）+ 兼容性加固（M15）+ **抗弱模型格式指令改为内置自动注入**。自此**版本号默认从 1.0 起**。
  - `v1.1.0`：UI/可用性整理：① 设置面板改为**可折叠抽屉**（对齐酒馆助手 / 鸡尾酒 等原生扩展观感，默认折叠）；② 「📒 名册」按钮移到**原生按钮栏** `#leftSendForm`（与 ☰ / 🪄 并列，原为右侧 `#rightSendForm`）；③ **补齐小手机工坊设置项**（显示模板条 / 打开工坊 / 自有 API 三项配置）——此前 README 说"设置里能配自有 API"但面板里根本没有，工坊等于没有入口；④ 悬浮窗视觉美化（分段式标签、圆角阴影、主题色标题栏、细滚动条、移动端断点）。
